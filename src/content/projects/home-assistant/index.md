## The problem

The setup had grown over two years of adding things, and a lot of what looked automated didn't work. An audit found 15 automations failing silently: reminders sent to a phone that was no longer paired, a "living room" vacuum script that cleaned the kitchen, and an AC thermostat where choosing *Cool* turned the unit off. The database had grown to 435 MB with only ten days of history in it.

I treated it like any product with technical debt: review everything, rank the issues as broken, unsafe, unreliable and slow, fix them in that order — then design what was missing.

## A dashboard that only speaks up when something needs me

I designed a new dashboard in a dark, quiet style: one accent colour, Poppins, soft tiles. Instead of showing every sensor all the time, the top of the home view is a stack of **status banners** that appear only while they're relevant, each with its controls built in — the vacuum cleaning, the dishes being done, a door left open, the AC, the next laundry slot. When nothing is happening, the stack is empty.

The dashboard is generated by a small Python build script rather than edited by hand, so the design tokens, templates and phone and desktop layouts live in one place. Three custom web components fill the gaps no plugin covered: a weather hero, a week calendar and an embedded view of my calorie tracker. On the phone, the layout collapses to one column with a bottom navigation bar.

## Three integrations where nothing existed

When an integration was missing or broken, I wrote my own. All three install through HACS and are public on GitHub:

- **[ICA Lists](/projects/ica-lists/)** — shopping lists synced with ICA, mirrored from any to-do list so items show up sorted by store aisle.
- **[Lulebo laundry booking](/projects/lulebo-laundry/)** — booking the building's laundry room from the dashboard, feeding the laundry reminders and timer.
- **[LoCal](/projects/local/)** — my calorie and meal-planning app, restyled to match the dashboard and running inside Home Assistant.

## Rules written for real life

Every automation started as "when X, do Y". Making them reliable meant handling what actually happens at home:

- **Leaving, but not for the trash.** My phone has to be out of Bluetooth range for five minutes straight before anything happens — and then the lights dim to 30 % instead of switching off, so Rocky isn't left in the dark.
- **Welcome home.** The front-door sensor and Bluetooth presence together know I've just arrived: the hall light comes on, and after dark my usual lamps too.
- **The dishwasher as a state machine.** A power plug reads it as running above 10 W and clean after ten quiet minutes — but only if the run lasted 20 minutes or more. It survives restarts, and the banner stays until I tap "emptied".
- **The robot vacuum.** A daily clean at 10:00 if it's docked, a kitchen pass when the dishwasher starts (at most every three hours), a check that the tank was filled before mopping, and a remap button that backs up the map first.
- **Winding down.** At 21:00 the lights dim and the TV pauses; a DIY bed sensor turns everything off after a minute in bed.

## Faster, safer, lighter

| Area | Before | After |
| --- | --- | --- |
| Database | 435 MB for ten days — the bed sensor's raw voltage alone wrote twice a second | The chattiest sensors are left out of the history |
| Reliability | 15 automations failing silently | All fixed or removed, with restart-safe logic and a timeout on every wait |
| Lights | Each automation listed its own lamps and kept missing new ones | One light group used everywhere |
| Security | Account passwords in plain text in the main config file, and so in every backup | Moved to a separate secrets file |
| Voice assistants | About 150 entities exposed to Google, 90 of them raw sensors | An explicit list of the things worth talking to |

## The DIY layer

Most devices are off-the-shelf IKEA Zigbee and Matter-over-Thread. Where nothing fit, I built my own on ESP32 boards with ESPHome: a pressure sensor under the mattress, an infrared bridge for an AC unit with no smart features, a living-room climate sensor, and the [smart blinds](/projects/smart-blind/).

## What I learned

- **Restarts are a real event.** The dishwasher once reported "done" mid-programme: a trigger waited for the power to rise past 10 W, but it was already above. Now every state check reads the current value first.
- **Unofficial APIs will move.** ICA changed hosts without notice. The client now knows both, and a fake ICA server in the tests reproduces the move.
- **IDs aren't names.** Saving a new vacuum map renumbered every room, so anything that doesn't need a room number no longer uses one.
